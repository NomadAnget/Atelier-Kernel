## 目标

保持 Atelier Rust 内核职责、SDK 公开接口、消息契约、路由机制和业务域调用方式不变，整体重实现可靠性核心。结果必须减少状态所有者、锁依赖和资源驻留，而不是增加协调层；能以更少、更简单的状态转换和明确的资源所有权解释整个运行过程。

评估基线：556d7bd 加当前未提交的输出队列、持久日志修改。既有修改不是已完成的最终设计，允许整体整合、替换或删除，禁止为兼容临时补丁保留重复状态或通道。保留用户工作与持久数据，不 reset/clean，不触碰旁边生产实例。

## 不变的边界

- 不改变公开 SDK 方法、信封和回执类型、消息身份语义、路由地址或域间调用方式。
- 不引入业务工作流、业务调度体系、额外服务或中间件；仅使用既有 Rust/SQLite/独立 IPC 体系。
- 无效目标立即 TargetInvalid，不变成离线邮箱；同内容的新调用不被自动合并。
- Durable 不静默丢弃，失败不伪装成功；可能已执行而结果不明时明确收敛，不盲目重放。
- Volatile/Ephemeral 保留各自的非持久化语义；Observer 保持允许缺口、尽力交付，不承担业务提交保证。
- 普通持久日志可靠缓冲、事务导入；实时订阅副本允许丢失，瞬态进度及 console_only 保持原语义。
- 业务域不承担队列、重连、存储补偿、去重或进程故障管理代码。

## 实现方式约束

- 每份权威状态只有一个明确所有者；其他模块只查询或提交操作，不各自维护可变镜像。
- 生命周期、投递、管道和持久化之间以明确的所有权转移衔接，不增加全局协调器或通用调度框架。
- 不持全局路由/回执发布锁等待 SQLite、磁盘、管道 I/O 或进程退出。
- 子进程句柄、工作线程、连接、订阅和缓冲都有创建者、终止条件及回收路径。
- 完成结果以持久存储为依据按需读取；不以全量历史身份或结果常驻实现查询。
- 设计不能依赖无限内存或无限磁盘；资源不足时使用兼容的明确失败行为。

## 最终验收矩阵

- 兼容性：现有 SDK 调用、消息字段与类型、路由规则、四阶段回执与终态不可覆盖语义保持兼容；不改业务域通过验收。
- 持久化：锁库、提交失败、磁盘/容量不足、信封写入与状态更新各崩溃窗口，不产生假成功或静默丢失。
- 恢复：尤其覆盖管道已写完而目标未回执、目标已开始而结果未确认、终态已提交而回执未送达；无悬挂 Sent、无不安全重放。
- 生命周期：IPC EOF 但进程存活、启动失败、自启动/自重启、并发停止/更新、候选失败、旧代际迟到回执、后台退出与宿主释放。
- 资源：不读/慢读管道、持续洪峰、超大/未终止/损坏帧、慢观察者、长期完成结果与身份索引增长；其他域能继续前进。
- 日志：超过旧队列容量、主库长期锁定、缓冲写失败、导入失败、提交后清理前崩溃、重启去重、flush 确认及可靠接收成本。
- 简化：权威状态、可变镜像、锁依赖、后台线程和常驻缓存都有前后对照；不通过新增协调层转移复杂度。

## 已固定的所有权模型

- KernelLedger：消息身份、状态转换、持久恢复及账本/待发送信封的原子事务。Durable 真相只在 SQLite，完成结果按需读；非持久消息和未落库故障只在有界内存中。会话去重不靠全量历史索引常驻。
- 每条消息的短期互斥句柄：仅串行该消息的状态提交与发布；句柄弱索引可回收，不设全局回执发布锁。SQLite 等待不持路由表锁或全局元数据锁。
- 出口：只拥有本代际内存窗口、读取位置及单条正在写的帧；Durable 信封归账本事务，不在物理 flush 后过早丢失。终态提交后清理，故障写库失败时不能清除唯一信封。
- Supervisor：唯一持有 Child、停止信号和工作线程；不持 Child 锁阻塞 wait；停止/更新按域协调，不占用跨域全局控制锁；监控线程不得强持有自身退出依赖。
- Observer：有界尽力历史与订阅，不拥有业务状态，不参与提交；记录大小只计算一次，避免淘汰时重复序列化。
- 日志：独立 WAL 接收与原子游标导入维持原设计，由 LogStore 拥有并关闭 importer；健康字段只反映事实，不反向协调业务状态。
