## 目标与完成条件

修复最终复审确认的 R1–R6，在现有 Rust/SQLite/独立 IPC 内收敛数据库宿主所有权、来源准入、内部故障身份及关闭资源关系。保持现有 SDK 公开调用、消息格式、路由机制、投递策略及业务域调用方式不变。每份权威状态只有一个明确所有者，不新增协调服务、管理线程、业务工作流或业务补偿代码。

完成必须同时满足：六项契约回归由失败转为通过；原有 Rust 与双语言 SDK 套件保持通过；旧故障复现和资源回收成立；三平台 CI 覆盖原生进程行为；持久业务数据不静默丢弃，所有故障有明确结果。不得仅以编译或普通 CI 绿灯宣称可靠性完成。

## 按序执行清单

- [x] 0. 固定基线与契约断言。保存当前源码/工作区清单及六项证据，列出公开入口和旧退出排空语义；将现有探针转成要求正确行为的回归夹具，保留原失败观测。无需为重新证明已三次复现的问题再跑一轮旧行为。
- [x] 1. R1 / P1：同库唯一宿主所有权。在恢复性 UPDATE/DELETE 和其他可能修改已有数据的启动步骤前取得所有权；第二个宿主明确失败且不能碰活跃数据。所有权由现有持久资源所有者持有，退出和崩溃时可靠释放；不能长期霸占 SQLite 写事务或添加锁协调服务。处理相对/绝对路径和软链接等价路径，保留同宿主内部 storage/logger 多连接及纯内存模式。主要范围：lib/ledger 的初始化与释放。
- [x] 2. R2 / P1：域存储严格解码。查询的 params/data 解码失败明确返回存储错误，不伪造 null。`patch=true` 在原文损坏时拒绝修改，保留原始记录；合法 JSON null 仍合法，显式整体替换/既有 upsert 语义单独保留与验收。错误定位到表、记录和字段，不要求业务域自行读库或修库。主要范围：storage 解码、查询及 patch 路径。
- [x] 3. R3 / P1：统一代际准入与撤销。已撤销管道绑定不得再提交业务或注册处理器；正常 Spawning 首次注册、candidate、draining 的合法绑定仍可工作。与退出排空共审：不能因发送端失败而误拒原管道中已写完的回执，也不能让已撤销身份恢复 Active。撤销与入站处理采用一致的原子边界；外部故障、替换及已持来源锁的自操作复用同一内部逻辑，禁止递归加锁、全局大锁或另建协调层。主要范围：router 身份校验、注册、故障及替换入口。
- [x] 4. R4 / P2：内部失败来源与业务结果解耦。终态回收仅依据内核可信的持久化结果/内部状态，不能凭业务 data.persisted 或 error 字符串判定。复用或收敛既有失败存储，不新增一份长期驻留故障映射。保持真实未落库失败的既有 ExecutionFailed/persisted=false 对外结果、会话内重放及来源退出回收；正常终态身份及时清理。主要范围：ledger 状态转换、失败保留与 finish_publication，必要时核对 outbox 分类。
- [x] 5. R5 / P2：宿主关闭先于后台任务保活。顶层宿主先表达关闭意图，复用已有 shutdown 信号使候选等待和排队控制操作退出，再回收所属进程与工作线程。后台强引用不能阻止发出关闭信号；关闭过程中不得重新启动/注册进程，正常 Start/Stop/Restart/Update 能力不缩水。不新增后台关闭协调器，不靠任意延时或缩短更新超时掩盖所有权问题。主要范围：lib 宿主释放、supervisor 关闭入口及 router 控制线程。
- [x] 6. R6 / P2：统一静态与动态配置校验。抽取/复用 DomainProcessSpec 的基本身份和配置校验，boot、StartDomain、UpdateDomain、直接 spawn 均进入同一规则。非法候选在撤销旧进程、创建子进程或占用注册表项前失败；合法既有配置行为保持。主要范围：supervisor 配置校验与生命周期入口，router 现有错误反馈。
- [x] 7. 全局静态收尾。重新画出宿主所有权 → 代际绑定 → 消息提交/发布 → 关闭回收链，检查锁依赖、自操作重入、关闭期间的再准入及所有错误传播。清除被替代的分支/重复判断；核对宪法、审查记录与实现一致，不误改业务语义。
- [x] 8. 集中故障与兼容验收。一次性执行下表矩阵和既有套件，修复实际失败，形成结果与证据索引；只将实测平台计入通过范围。
