# 内核托管的域端口绑定

公开端口属于域与内核的绑定，不属于某个域进程代际。现有 kernel_boot.json 仍是唯一启动装配入口；未声明 ports 的域行为保持兼容。

```json
{"domain_id":"web","command":"node","args":["server.mjs"],"working_dir":"./domains/web",
 "ports":[{"name":"http","listen":"0.0.0.0:8790"}]}
```

每个绑定由内核自动启动一个薄转发子进程（同一 atelier-kernel 可执行文件的内部模式），只双向转发TCP字节，不解析HTTP、业务消息或业务数据。公开端口不随域换代变化。内核给每代进程分配独立的环回内部端点；Python/Node SDK统一提供 domain.bindings，映射值为 {host, port}。应用在on_start/onStart内完成内部监听并等待listen成功返回，SDK随后通过专用IPC报告应用就绪；仅注册消息处理器不足以使有端口绑定的候选提交。

更新时旧实例继续接收请求，候选初始化失败不修改入口。成功后转发目标切换，已建立连接仍留在旧实例；内核后台按连接计数排空并回收旧实例，最多等待30秒。SSE/WebSocket在此期限后可能断开，由客户端重连；不会把连接内容或会话状态自动迁移到新进程。UpdateDomain回复可通过旧HTTP连接正常返回，不等待该请求自己的连接排空。

转发进程失败由内核自动恢复到当前后端。转发进程退出时已有连接不能保留。内核退出时控制管道EOF使转发子进程退出，释放公开端口；显式停止业务域仅撤销后端目标，公开监听由内核继续持有。端口暂时无后端时关闭新连接。

绑定名称和公开地址在一次代码滚动更新中固定。修改/增删一个运行域的公开端口绑定需要单独迁移，当前返回明确错误并保留原域；普通代码、环境变量、内部端点更新不受此约束。首次从域直接占用公开端口切换到内核托管，需要一次宿主重启以释放旧监听。新版绑定需要新版SDK；旧SDK不会报告应用就绪，候选因此拒绝提交。

跨域业务通信仍严格使用内核IPC消息契约，不能用内部TCP端点绕过域边界。ATELIER_PORT_BINDINGS、ATELIER_MANAGED_READY为内核保留环境变量，启动配置不允许伪造。

验证：Python/Node真实双端口、延迟启动、原始启动错误回传、候选失败保留旧PID和入口、旧连接排空、转发进程崩溃恢复、主机关闭释放端口；真实Web隔离自更新连续18次健康探测0失败，stop/restart权限403。本地Windows已交叉编译检查；原生三平台运行结果以0.1.14发布工作流为准。
