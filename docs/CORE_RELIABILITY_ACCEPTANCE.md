# 核心可靠性重实现验收记录

日期：2026-10-21。范围：`atelier-kernel-observer-fix`，实现基线 `c1b7213`，用户阶段备份 `6102221`。其后改动保留在本地，未追加提交、发版或替换变体服务。

## 模块边界与最终规模

| 模块 | 处理方式 | 最终责任和简化 |
|---|---|---|
| Ledger | 主体重实现 | Durable 事实/完整信封/提交索引同事务接收；历史直接查 SQLite；私有内存只保留非持久结果、有界在途元信息及未持久故障反馈 |
| Router | 保留路由/权限/内置接口，重整接线 | 去掉全局发布锁及生命周期专用来源表；按消息发布；调用序号、回执、注册和订阅绑定真实进程代际 |
| Outbox | 保留已有有限内存/SQLite 机制，收敛边界 | 每代际一个出口；业务信封直到账本终态提交才删除；物理写入只推进出口游标；关闭与接收串行 |
| Supervisor | 主体重实现 | 每域一份状态；Child、停止信号和工作线程归一个所有者；拿走所有权后 kill/wait/join；监控只用 Weak，移除自持重启队列 |
| Observer | 主体替换 | 一把短锁拥有事件编号、有界历史及非阻塞订阅；每条大小只算一次；删除第二套域出口字节额度 |
| 日志 | 保留独立 WAL/原子导入游标模型，收尾资源与事务 | 接收提交与实时副本分离；导入提交后再清理；所有写事务先取得写入权，避免并发快照升级竞争 |
| 存储/协议/纪律 | 主体保留 | 按域隔离、字段和消息类型保持；纪律检查覆盖新的内部提交索引 |
| Python/Node SDK | 保留公开方法和签名 | 内部入站执行有界，与出站请求额度独立；所有内核流的慢异步回调复用尽力隔离，不增加业务调用参数 |

不是以缩减代码行数作为成功标准。SQL 事务、退出边界和验收夹具明确展开后，一些源码行数增加；删除的是重复事实所有者、全局阻塞锁、结果副本与自持资源环。没有增加服务、协调器、业务调度或依赖包。

## 最小状态转换与所有权

1. 内核认证来源及其代际，按该会话的序号分配父/子身份。无效目标直接 TargetInvalid。
2. 有效 Durable 在一笔 SQLite 写事务中接收 Sent、完整信封和提交索引；任一步失败就不交付，按原回执契约报告失败。
3. 该代际出口按有限窗口写 IPC。flush 不代表目标收到或执行成功，完整信封继续保留。
4. 目标同代际回执按消息串行推进 Received、Started、Completed/失败。终态事实与信封清理同事务；终态不可被迟到回执覆盖。
5. 连接结束先关闭出口，再用有界在途元信息收敛对应代际。旧来源的结果不会进入同名新来源；旧目标无法确认新目标的消息。
6. 宿主恢复时，在事务中把所有旧非终态收敛为明确失败，执行结果可能未知；不重放可能已产生副作用的业务。已提交终态和结果仍可按原身份查询。
7. Supervisor 是 Child/工作线程的唯一进程资源所有者。退出/更新只转移这份所有权；路由表锁、进程状态锁不跨 wait/join 或 SQLite 等待。
8. Observer 和实时日志只是有界副本。普通持久日志由独立 WAL 接收，主库的导入数据与游标原子提交，清理窗口崩溃后不会重复导入。

未落库的基础设施失败覆盖仅在当前宿主中明确反馈，不能声称其已持久。Volatile 历史保留原宿主内存语义，达到内部额度时拒绝新请求；Ephemeral 完成后回收。动态受管域登记也有内部上限，额度满不影响已有域的控制。

## 保留的语义及验证范围

- Observer、遥测、通知及实时日志副本允许缺口；订阅 API 不增加容量、背压或积压参数，未升级为持久事件系统。
- 持久业务接受以成功事务为界；存储失败绝不发布未持久化的成功。不承诺 exactly-once 外部副作用；结果未知不会被当作未执行而自动重试。
- 持久日志恢复依赖独立缓冲仍完整可读；缓冲本身无法写入时明确报错并保留健康故障，不假装接收成功。操作系统杀死宿主走恢复路径，不能承诺永久磁盘故障下继续成功接收。
- `UpdateDomain` 保留既有注册就绪、原子切换和宽限后退出行为；业务级健康探活/无损安全更新仍是用户暂缓的独立需求，未把它混入本次重实现。
- 本次实际运行验收环境为 Linux/WSL；没有声称 Windows 原生进程运行也已实测。

## 子进程退出回执与终态发送失败复核（2026-10-21）

- macOS CI 暴露的真实竞态已用确定性夹具复现：OS 子进程退出并不代表接收线程已读完其管道。原 `ManagedProcess::exited` 提前触发故障清理会打断最后的 Received/Started/Completed。
- 修复后接收线程拥有故障前的输入排空边界；OS 退出、发送线程失败或出口故障只请求排空，接收处理结束后才撤销该代际。主动停止/重启仍立即取消。排空遇 EOF/当前无数据即结束，并有内部 16 MiB 总量限制，避免继承写端或持续坏输入无限占用；Windows IPC 使用 PeekNamedPipe 实现同一可中断读取行为。
- 截图“发现 B”补测结论：未证实持久终态因 `finish_publication()` 丢失。成功及失败终态均先提交账本；即使原代际不存在而无法投递回执，清理后的 `message_id`、`logical_id` 仍可通过现有 Rust 账本方法读出完整终态，重新打开内核后仍成立。同一源会话的显式重复提交可重放终态，不能重复执行目标。
- 注入终态持久化失败并同时使回执不可达：保留存活会话的失败身份，返回状态为 ExecutionFailed/persisted=false，不伪装为成功或持久终态。
- 边界：上述查询验证针对 Rust KernelLedger 现有 API；现有跨进程 SDK 没有按旧 ID 查询账本/重启后自动取回旧回执的协议。新源进程不接收旧代际的主动补发；观察历史查询也不是完整持久结果接口。这里没有新增查询、重连或业务补偿接口。
- 证据：`tmp/core-final-acceptance/exit-drain-before.log`（修复前确定性失败）、`exit-drain-all.log`、`exit-drain-windows-check.log`、`receipt-publication-check.log`。
