# 进程回收可见性

契约：**一个域的 PID 在它的清理真正完成之前，必须持续可查。**

这条约定决定了"进程还在不在"和"域还在不在服务"是两件不同的事，调用方不能靠 `get_pid` 为 `None` 反推进程已经消失。

## 行为

- 内核移出进程所有权时，**原子记录待回收 PID**，`get_pid` / `QueryRuntime` 继续返回它。
- 只有在 `wait` 与工作线程 `join` 都完成之后，才清除这个待回收 PID。
- 执行槽位与待回收身份属于**同一进程代际**，由同一把生命周期操作锁串行管理。
- `kill` / `wait` / `join` 全程**不持有状态锁或路由锁**；查询不等待 operation 锁，因此回收慢不会把查询卡住。
- 主槽位回收遇到 `Interrupted` 会重试 `wait`；其它 `wait` 错误保留 Child 与 ManagedProcess 所有权，PID 不清空，也不启动替代进程。同步 stop 在该路径返回 `false`，restart 返回既有的 `SpawnFailed`，**不假报"新进程已启动"**。
- 滚动更新的 PID 表示**当前代际**；切换到新 PID 不代表旧代际已经回收完毕。查询不会被扩展成"全代际进程清单"。

## 边界（不要误解）

- **PID 存在 ≠ 服务就绪**。能不能调用仍由路由与 `Active` 状态决定。
- 不覆盖：操作系统永久拒绝 `wait`、内核被强杀、整机掉电之后的状态。
- 不新增 SDK API、订阅参数，也不要求业务域做补偿逻辑。

## 对应测试

`supervisor` 的进程回收用例：故障回收、手动停止、手动重启、自动重启四种路径，都要求清理 `join` 阶段阻塞时查询仍**及时返回旧 PID**，放行后才观测到 PID 消失且状态符合预期（停止保持停止、重启得到新 PID）。
